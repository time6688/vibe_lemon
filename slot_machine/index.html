SWAG 老虎機小遊戲

版本 v0.1　·　狀態：待商業團隊確認　·　本文件不含技術細節

用戶在 SWAG 站內拉一次拉霸，三個轉軸停下後依照圖示組合決定獎勵。核心目的不是做一個遊戲，而是給用戶一個「每天回來」與「多花一點」的理由。

01為什麼要做

這個小遊戲想同時解三件事，優先順序建議如下：

提高回訪

每日免費一抽，製造一個低門檻的「今天要打開 App」的理由。

拉高消費頻次

把抽獎次數綁在儲值或消費上，讓原本會買一次的人多買一次。

導流到內容

獎品不只給鑽石，也給觀看通行證，把獎勵直接轉成內容消費。

成效怎麼看，建議追蹤：每日參與人數 人均抽獎次數 參與者 vs 未參與者的當週消費差 獎勵發出後 7 日內的使用率

02用戶玩起來是什麼樣子

  1. 進入活動頁從站內活動入口或站內通知點進拉霸機頁面，身分自動帶入，不需要登入。
  2. 看到自己還有幾次畫面上方明確顯示「今日剩餘抽獎次數」與取得更多次數的方式。
  3. 拉一次按下拉桿，三個轉軸依序停下，約 2～3 秒。沒有次數時按鈕改為引導取得次數。
  4. 看到結果中獎跳出獎項彈窗；沒中也給明確回饋與再試一次的引導，不要只是安靜停住。
  5. 獎勵入帳鑽石／通行證直接進帳戶，不需要另外領取。頁面下方可查看自己的中獎紀錄。

03遊戲規則

三軸拉霸，共 6 種圖示。以三軸相同或特定組合判定中獎，規則一眼看得懂，不做複雜連線。

組合說明獎項等級
7　7　7三個紅七頭獎
BAR BAR BAR三個 BAR二獎
任三個相同水果葡萄／檸檬／櫻桃各自成組三獎
任兩個相同安慰獎，維持手感四獎
其他未中獎—

一定要有保底。建議設計為「連續 N 次未中獎，第 N+1 次必得四獎」。純機率會讓少數用戶連續槓龜十幾次，那是最容易流失也最容易客訴的一群人。N 值建議 8～10。

設計說明

  • 機台是懷舊實體風，介面是 SWAG 深色系。機台本體刻意做成鍍鉻＋深藍＋金邊的經典拉霸樣式製造反差與辨識度，周圍的按鈕、文字、彈窗則沿用平台既有的深色介面與品牌色，不會讓人覺得跳到另一個 App。
  • 轉軸依序停止。左中右間隔約 0.45 秒停下，最後一軸停下前是整個體驗最緊張的瞬間，這個節奏不要壓縮。
  • 拉桿是裝飾也是引導。桌機可點拉桿觸發，手機則以主按鈕為主，拉桿同步做出下拉動作，維持儀式感。
  • 六種圖示：紅 7、BAR、金鈴鐺、葡萄、檸檬、櫻桃。全部以向量繪製，不使用外部圖檔，確保載入速度與各機型清晰度。
  • 未中獎不能安靜。沒中也要有明確回饋與下一步引導，否則用戶會以為壞掉。

以上為互動原型，不是最終視覺稿。正式開發前仍需設計師產出主視覺（含活動主標、背景、獎項圖、四語系版面）。這份原型的用途是讓大家在投入設計資源前，先對「動起來是什麼感覺」有共識。

06抽獎次數從哪來

這是整份 spec 最關鍵的商業決策，直接決定遊戲是「留存工具」還是「營收工具」。三種模式可擇一或混搭：

最快上線

A. 每日免費一抽

每人每天一次，零門檻。純留存導向，不直接帶營收，但開發最單純、合規風險最低。

建議主力

B. 消費滿額換次數

當期消費每滿一定金額換一次抽獎。獎勵的是既有消費行為，屬於回饋性質而非付費博弈，合規上相對單純。

需先確認可行性

C. 直接花鑽石抽

每抽扣固定鑽石。營收效果最直接，但這是付費隨機獎勵，合規與技術前提最多。

⚠ 開工前必須先確認

模式 C 需要平台端提供「扣除用戶鑽石」的能力。目前我手上的平台文件只有「發放鑽石」，沒有任何扣款機制。若確定要做 C，請先向平台工程確認這個能力是否存在——若不存在，模式 C 在現階段無法實作，只能改走 A 或 B。

07上線範圍建議

階段包含不包含
第一版 三軸拉霸、四級獎項、保底機制、每日免費一抽（模式 A）、個人中獎紀錄、四語系介面 排行榜、社群分享、活動期間限定主題

第一版刻意不做付費抽，先用免費抽驗證「用戶到底愛不愛玩」。如果免費都沒人玩，付費版本也不會有人玩。

08需要商業團隊決定的事項

  • 抽獎次數的取得方式A／B／C 擇一，或第一版 A、第二版 B
  • 四個等級的實際獎品與數量特別是頭獎要多大才有話題性
  • 各獎項機率與每日總量上限需搭配期望成本試算
  • 活動檔期常駐功能，還是限期活動？限期則需明確起訖時間
  • 入口位置首頁活動區、站內通知，或兩者都要
  • 機率是否對外公示見下方合規提醒，建議法務先看過
  • 活動文案與主視覺方向標題、規則說明、獎項文案、四語系翻譯

09風險與合規提醒

  • 機率公示：若採用付費抽（模式 C），台灣對線上遊戲的隨機獎勵有機率揭露要求，各獎項機率需明確標示於活動頁。請法務在定案前確認，這不是技術層面能決定的事。
  • 賭博觀感：拉霸機的視覺本身就帶有博弈聯想。文案上建議統一以「獎勵活動」「幸運轉盤」定位，避免使用賭場語彙。
  • 成本失控：務必為每個獎項設定每日總量上限。沒有上限的話，機率一旦估錯或被異常流量放大，損失是沒有天花板的。
  • 用戶客訴：中獎紀錄必須可查、獎勵必須可追蹤。「我明明中了但沒收到」是這類活動最常見的客訴，事前把紀錄做好比事後一筆筆查便宜得多。

10本次不做的事

先寫清楚，避免後續期待落差：不做多人對戰、不做玩家之間的獎品交易或轉贈、不做跨日累積的拉霸點數系統、不做實體獎品寄送。
